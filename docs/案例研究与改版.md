# 案例研究与改版

2026-10-18 · 智鉴界面第二版。

## 1. 上一版的问题

上一版把品牌展示放在任务之前：首页与证据页都有刻意分行的口号，辅助英文、档案编号、状态标签重复出现；文字说明小且密，圆角卡片又把同一条信息分成很多层。聊天里每条线索下面都放操作入口，阅读节奏被按钮打断。结算以大号分数和宣言居中，关键错误反而在后面。

用户需要的是能看清案件、读懂聊天、判断访问权限的移动应用。第二版保留功能与安全规则，重新组织页面的阅读顺序，不靠改配色掩盖结构问题。

## 2. 本次查阅的案例

下列是官方设计案例与说明。Things 和 Signal 的参考图为历史版本，用于分析设计方法，不作为它们当前版本的描述。

| 案例与来源 | 查阅内容 | 智鉴借鉴的原则 |
| --- | --- | --- |
| [Things 官方功能介绍](https://culturedcode.com/things/features/)及其中的 iPhone Today 截图 | 主标题、列表层级、次要信息收纳与分组 | 用明确标题和列表组织任务，详情按需出现，保持连续阅读 |
| [Things 官方设计说明](https://culturedcode.com/things/blog/2017/11/hello-x/) | 减少装饰、让内容自然延伸的设计思路 | 删除无任务作用的口号、额外边框与英文装饰 |
| [Signal 官方消息请求案例](https://signal.org/blog/message-requests/) | 联系人上下文、消息流与决策动作的位置 | 聊天像聊天，身份信息放在联系人附近；收集线索通过消息操作出现 |
| [Android 官方隐私与权限案例](https://www.android.com/intl/en_us/safety/privacy/) | 权限管理与访问范围的表达 | 使用熟悉的权限名称与逐项选择，让用户知道正在给什么访问 |
| [Android 官方隐私信息中心说明](https://support.google.com/android/answer/13530434?hl=en) | 按访问类型检查信息的路径 | 按摄像头、相册等真实语义分组，详细选择再进入一层 |

实际查看了 Things 的 Today 页面和 Signal 的消息请求图。Android 案例查阅了官方页面中的权限语义说明与操作步骤。第三方截图只作研究，未放入应用资源或作为本项目成果交付。

## 3. 从案例到第二版

| 位置 | 第一版 | 第二版 |
| --- | --- | --- |
| 首页 | 两行口号、英文眉题、大卡片与波形 | “安全练习”直达任务，三个情境连续排列，正在进行的情境显示进度 |
| 文字 | 重点文案人为断行，辅助字号过小 | 中文按自然句子排版，正文 16、说明 14，标题不强制拆行 |
| 聊天 | 每条消息带一组取证动作，提示提前给答案 | 保留消息流，点选消息后出现操作；已收集消息显示一个轻量标记 |
| 媒体分析 | 大波形、多个状态胶囊与底部按钮重复 | 一行素材入口、直接的观察结论、三项指标，依据用普通正文解释 |
| 权限 | 七个下拉框常驻，风险数值占据大面积 | 权限名称与当前选择组成列表，点开再选；风险浓缩为一行和细条 |
| 线索 | 未发现的内容也占据四个重复位置 | 仅展示实际收集的线索，缺少数量单独提示，未发现答案不预先公开 |
| 结果 | 居中的大分数、宣言、三根条和长解释 | 先说结局与原因，分数与能力项对齐排列，再看具体错误 |
| 品牌 | 通用指纹图标，品牌与业务图标混用 | 独立的“对照之窗”图形，搭配中文“智鉴”，业务图标继续用统一线性风格 |

## 4. 改版边界

原有八类页面、三个案例、40 / 30 / 30 评分、权限三态、独立失败判定与本地存档设计均保留。第二版不减少课程要求，不将视觉样机宣称为 Unity 成品。

第一版图保留在 `docs/ui/`，第二版图放在 `docs/ui/v2/`。当前执行基准是 [UI 美术规范](UI美术规范.md) 与 [品牌标识](品牌标识.md)，后续实现不再沿用第一版口号式标题和深色大卡片模板。
