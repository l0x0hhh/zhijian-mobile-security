# 开发计划

计划原则：先完成一个案件的纵向闭环，再复用到其余案件，最后补素材、适配和报告。暂无课程截止日期、团队人数或现成 Unity 编辑器信息，不预设工期或成员姓名。

以下路径均为预计新增或修改的文件，不表示文件已经存在。阶段开始前应结合实际情况向刘总报出具体清单；业务代码需要适用授权，文件开头附简略注释，完成后汇报实际改动，不自动编译验证。

## P0：设计与版本管理（本轮）

范围：落地设计、课程需求映射、开发顺序与素材记录模板，初始化 Git 并推送指定 GitHub 私有仓库。

本轮文件：`AGENTS.md`、`README.md`、`.gitignore`、`.gitattributes`、`.editorconfig`、`docs/顶层设计.md`、`docs/需求与验收.md`、`docs/开发计划.md`、`docs/素材台账.md`。原始课程 PDF 原样纳入版本管理。

完成条件：设计相互一致、要求有对应实现位置、首个提交成功推送、远端为私有、本地与远端提交一致。仅检查文档与 Git 状态，不声称程序能运行。

完成条件：工程版本与 Android 模块选择明确；主界面、返回栈、安全区域与文字规范有统一承载位置；开始、选关与五类入口布局齐全。业务功能仍可用占位内容说明未完成，不伪装为完整案件。

## P3：语音借款纵向闭环

预计文件：

- `Data/Cases/VoiceLoan.asset` 与案例目录引用。
- `Scripts/Presentation/Chat/ChatPresenter.cs`、`MessageView.cs`、`MediaMessageView.cs`。
- `Scripts/Presentation/Investigation/EvidencePresenter.cs`、`DetectionPresenter.cs`、`PermissionPresenter.cs`、`VerificationPresenter.cs`。
- `Scripts/Presentation/Results/ConclusionPresenter.cs`、`ResultPresenter.cs`。
- `Prefabs/Pages/` 下的聊天、检测、权限、核验、证据提交、结果页；`Prefabs/Messages/` 下六类消息组件。
- `Media/VoiceLoan/` 下的已授权语音、文字稿及必要图片；`docs/素材台账.md`。

完成条件：一个案件能表达查看、取证、检测、权限、核验、提交、结局、复盘的完整链路；四处置选项齐全；立即转账无须完成调查也会失败；三维分数和错误原因能追溯。此时优先修正公共流程，避免把缺陷复制到后两关。

## P4：复用换脸会议与证件照案件

预计文件：

- `Data/Cases/FaceMeeting.asset`、`PhotoPermission.asset` 与案例目录。
- `Scripts/Presentation/Apps/AppDetailsPresenter.cs`、`SimulatedInstallPresenter.cs`。
- `Prefabs/Pages/` 下应用详情、隐私政策、模拟下载与安装页。
- 七权限展示与指定照片范围组件，必要时补充公共权限数据和规则。

完成条件：换脸检测有指定三指标，安装加敏感授权可失败；案件三无聊天和检测门槛，七项访问和四条证据齐全。新增案件主要改配置；如需要复制整套公共页面或规则，先回查架构边界。

## P6：最终交付准备

预计文件：`docs/需求与验收.md` 的真实结果记录、`docs/素材台账.md` 的授权记录，以及课程报告和附录。APK、工程压缩包放入单独交付目录，不混入源码提交；当前未生成这些产物。

完成条件：按课程现场流程准备安全 / 失败两条演示路线、退出重开成绩、脚本与配置讲解、最终 Android 权限清单和素材说明；报告只写已实际发生的实现与检查结果。

## 开发期间的 Git 约定

默认分支 `main`。后续每个获准实施的阶段使用清晰提交，如 `feat: add investigation rules` 或 `docs: record case assets`；阶段改动较大时再开功能分支。当前不为文档初始化创建空 PR。

保留 Unity `.meta` 与资源成对提交；工程版本和包锁定文件一并提交。不要提交缓存、密钥或构建产物，也不要在 Unity 工程建立前添加自动构建工作流，以免产生没有意义的运行结果。当前 `.gitattributes` 不依赖本机未配置的合并驱动或 Git LFS。
