## 后续执行前提与记录

由主窗口另行安排运行。使用只含虚构数据的独立 QA 目录，由 JsonProgressRepository 构造参数传入；不要使用 Application.persistentDataPath 中已有的正式学习记录。故障场景需可控仓储/平台故障入口或备份后的专用测试副本；本轮没有实现故障注入器，缺少入口就保留未执行。

记录工程修订与本地变更、实际工具/设备、用例 ID、原始文件哈希、输入结果 ID/Sequence/案件及版本、步骤、预期、实际、状态和证据。普通 CaseResult 应通过正常领域终局取得，不能假造未冻结结果。格式边界可用独立 QA 归档模型构造，但不得冒充现行剧情可达的业务结局。涉及文件故障的操作仅针对 QA 副本。

主路径为 progress.json，备份为 progress.backup.json；正式 UI 负责在 RecoveryRequired 时取得明确确认，存档实现不自行弹窗或默认同意。运行时持有同目录唯一的 ProgressService 和 JsonProgressRepository；本实现没有提供多进程锁或多个仓储实例间的并发保证。
