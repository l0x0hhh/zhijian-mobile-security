## 2. 冻结存档接口

实际代码已经存在：

- `Scripts/Application/Ports/IProgressService.cs`：`IProgressService : IDisposable`。
- `Scripts/Application/Progress/ProgressSnapshot.cs`：只读模型、加载/保存状态、写入反馈。

核心接口：

```csharp
ProgressSnapshot Current { get; }
event Action<ProgressSnapshot> Changed;
Task InitializeAsync();
Task<ProgressWriteResult> RecordAsync(CaseResult result);
Task RetryPendingAsync();
Task StartNewSaveAsync();
```

主窗口给 Result/Records Presenter 注入 IProgressService，不引用具体 JSON 或文件实现。S3-C 交付 `ProgressService(IProgressRepository repository)` 和 `JsonProgressRepository(string directory)`；仓储接口及内部 DTO 可在其独占范围内设计。运行时 directory 由主窗口传入 `Application.persistentDataPath` 下的专用子目录，不能在存档实现里猜固定盘符。

### 状态与显示数据

- ProgressLoadState：NotLoaded、Loading、Ready、RecoveredFromBackup、RecoveryRequired、Incompatible、Failed。
- ProgressSaveState：Idle、Pending、Saving、Saved、Failed、Blocked。
- ProgressSnapshot：Cases、RecentResults、PendingResultCount、StatusMessage、LoadState、SaveState；CanWrite 仅在 Ready/RecoveredFromBackup 为真。
- CaseProgress：CaseId＋ScoringRuleVersion、BestTotalScore、BestSafeScore（可空）、HasSafeClear、LastResult。
- SavedResult：ResultId、CaseId、CaseTitle、两个版本、Sequence、ResolvedAtUtc、Outcome、三分项、TotalScore、ScoreEntries、Feedback。
- ProgressWriteResult：原 ResultId、保存状态、适合显示的 Message。其反馈状态只能是 Saved/Pending/Failed/Blocked。

模型构造函数以实际源文件为准。不要另建同名模型，不改变参数顺序、名称或枚举值；不能把完整 CaseDefinition/SessionState 当持久化 DTO，也不向 View 透出正确答案。

### 方法行为

| 方法 | 必须保持的行为 |
| --- | --- |
| InitializeAsync | 只初始化一次，串行处理加载；异常文件转为明确状态。加载前不得把默认空数据写回覆盖已有文件 |
| RecordAsync | 只接受已冻结 CaseResult；按 resultId 去重；首次接收分配单调 Sequence，失败重试复用原顺序。处理普通 IO 失败时保留待保存数据并返回 Failed/Pending，不能改业务结局 |
| RetryPendingAsync | 合并全部待保存结果，串行重试；不得重复计数或改变 lastResult 的产生顺序；只读不兼容状态不得写 |
| StartNewSaveAsync | 仅用于 RecoveryRequired 且 UI 已明确确认“保留损坏原件后新建”；先归档坏文件。Incompatible 必须拒绝新建覆盖，不能偷退到旧备份 |
| Changed | 在创建服务的同步上下文发布一致快照；通知失败不当作写入失败，不允许通知回调重入修改队列；无 UI 订阅也必须可以工作 |
| Dispose | 解除订阅/停止接收新请求；不得删除存档。未实际落盘的结果不能宣称关闭或强杀后可恢复 |

保存规则：最高总分与最高安全分分别聚合，失败不清安全标志；历史最多 10 条，但最高分、最近结果、旧案件及评分版本聚合仍保留。resultId 去重记录不能随 10 条显示历史的裁剪而立即丢失。顺序使用 Sequence，不使用保存重试时间或系统时钟决定 lastResult。

主档→同目录临时文件→重新解析校验→平台可行的安全替换→保留有效备份。主档损坏才尝试有效备份；未知较新 schemaVersion 进入 Incompatible，不能退到旧备份覆盖。所有持久化类型由 S3-C 显式 DTO 转换，JSON 序列化放 Infrastructure，Application 不引用 Unity。

1. 所有并行窗口停止编辑并交付文件/哈希/未验证记录；主窗口只读复核各独占范围与接口，不用 Git reset/stash/clean 处理共享目录。

4. 继续按刘总要求不自动编译或运行 Unity。后续人工导入/运行、资源播放与保存恢复结果要如实单独记录；静态完成不等于真机或 APK 通过。
