# 智鉴顶层设计

版本：0.5；设计日期：2026-10-16；修订日期：2026-10-18；状态：P1 预览界面、领域规则及 P2 首批内容/应用用例已落盘；完整案件操作页、媒体与存档待接入。

本次将引擎基线调整为刘总现有的团结引擎 `2022.3.61t10`，细化 MVP、程序集依赖、会话所有权和存档版本。业务规则保持提交门槛、权限三态与用途、分项评分、模拟移除和消息触控分工。实施边界与源码研究见 [代码架构设计](代码架构设计.md)，视觉规则见 [UI 美术规范](UI美术规范.md)。

## 1. 目标与范围

把课程要求落成一款可在 Android 真机演示的离线互动应用：以三个完整案件训练“识别与取证、权限判断、安全处置”，能够说明每一次得失分及其安全含义。

基础版覆盖三个案件、虚拟手机桌面、聊天与本地媒体、模拟检测、权限审查、证据收集、身份或来源核验、双结局、知识复盘、本地成绩与移动适配。三个案件默认可选，便于课堂直接演示。

基础版不训练 AI 模型，不连接真实检测 API，不做真实支付、拨号、安装或系统权限授予，不包含后端、登录、排行榜或广告。聊天外链只进入应用内模拟页面。素材与存档均保留在本地。

角色与核心任务：玩家扮演移动安全分析员，按证据判断，不能只凭“检测器说是假”下结论。检测输出必须标注“教学模拟”，不包装成真实检测能力。

## 2. 体验与页面结构

采用竖屏虚拟手机。页面使用统一标题栏和返回行为；调查页共享证据入口与当前案件上下文。第二版以暖白、墨绿和自然中文排版组织任务，风险使用陶土色、失败使用红色并配文字；夜间保留相同结构。顶栏使用“对照之窗”Logo，业务图标不承担品牌标识。具体排版与动作位置由 UI 美术规范统一管理，不再沿用第一版口号与大卡片布局。

## 3. 三个案件

以下人物、应用和剧情名称均为设计占位，制作素材时使用虚构身份。

### 案件一：熟悉的声音，陌生的收款人

- 背景：自称好友的人使用新账号发来克隆风格语音，以紧急情况催促借钱。
- 四条关键证据：新账号、收款人与好友不符、语音停顿异常、拒绝通过原号码回拨。
- 模拟检测：语音韵律、停顿衔接、背景噪声三个预设异常指标；只作为辅助证据。
- 核验：通过通讯录中原有联系方式联系本人为可靠方法；追问当前账号、只相信语音或拨打对方新发号码不可靠。通讯录是案例内虚拟联系人。
- 至少四个处置：原联系方式核实并拒绝转账、立即转账、继续向当前账号追问、按对方链接做核验。
- 安全路线：完成调查，可靠核验，识别冒充诈骗，拒绝转账并保存证据。
- 失败路线：“立即转账”在任意调查阶段均立即终止并进入诈骗结局；不因前置步骤未做完而屏蔽该后果。
- 权限环节：增加一个“转账验证助手”模拟诱导页，供安全中心审查其权限。此项是为覆盖通用权限操作的设计扩展，不要求真的安装应用，也不能取代语音借款主线。

### 案件二：会议中的领导，非官方的安装包

- 背景：虚拟领导的视频要求安装所谓会议工具。
- 四条关键证据：音画不同步、面部边缘异常、光照不一致、下载来源非官方。另可加入短信和通讯录越权作为补充证据。
- 模拟检测：固定包含音画同步、面部边缘、光照一致性三项指标。
- 权限：模拟应用至少索取短信和通讯录，安全判断为拒绝；页面可先查看声明，审查不依赖实际安装。
- 核验：通过已知官方渠道或原有联系方式确认会议安排。
- 安全路线：完成调查，拒绝未知安装包，拒绝越权，保存证据并报告风险。
- 失败路线：模拟应用处于已安装状态时，授予短信或通讯录中的任一权限，触发恶意应用结局。安装状态或权限改变后均检查该条件，不能通过改变操作顺序绕过。
- 仅点击下载或仅模拟安装不会自动算作上述失败条件，但须产生风险提示；安全结案前需取消安装或移除模拟应用。应用详情按状态提供“取消下载 / 删除安装包 / 移除模拟应用”，未触发终局时可以补救；终局一旦触发，移除不能回滚失败结果。

### 案件三：一张证件照，七项权限

- 背景：未知开发者的证件照应用要求广泛授权。
- 四条关键证据：功能与权限不匹配、开发者信息不明、隐私政策过度授权条款、强制后台运行与证件照功能无关。
- 入口为应用详情与隐私政策，不展示无关聊天，不要求媒体检测。
- 七类权限：摄像头、相册、麦克风、通讯录、短信、定位、后台运行。后台运行是教学中的访问能力类别，不宣称对应某个统一的 Android 危险权限。
- 摄像头与指定照片按需允许；默认不要求两者同时授予，可以选择拍摄或指定照片路径。案例内不实际拍照或读取相册。
- 相册采用“仅指定照片 / 全部相册 / 拒绝”的范围区分，不能把全部相册访问等同于指定照片。
- 核验改为检查开发者及分发来源；不是要求玩家给虚构人物回拨。
- 安全路线：按功能选择最小访问范围，拒绝其余访问，识别过度授权并拒绝使用该不可信应用。
- 失败路线：提交时仍允许任一非必要权限或全部相册访问，则进入隐私泄露风险结局。

## 4. 技术决策

| 决策 | 选择与理由 |
| --- | --- |
| 引擎 | 团结引擎 `2022.3.61t10`，本机入口 `E:\unity\2022.3.61t10\Editor\Tuanjie.exe`；由实际编辑器生成 ProjectVersion.txt，不手写伪造版本 |
| 界面 | uGUI + TextMeshPro，便于预制体搭建手机界面、滚动消息和弹窗；首版不混用 UI Toolkit |
| 场景 | 一个 Main 场景，AppRoot 组合服务，页面预制体切换，避免跨场景状态丢失 |
| 内容 | ScriptableObject 案件资产与媒体引用，三个案件只配置内容和规则差异 |
| 业务 | 纯 C# Domain、Application、Presenter；以 `.asmdef` 固定边界，AppRoot 显式组装，少量结局策略处理案件差异 |
| 媒体 | 本地 AudioSource / VideoPlayer，媒体转为目标设备兼容的格式后再验收；不播放远程 URL |
| 存储 | persistentDataPath 下的版本化 JSON；通过仓储接口隔离文件操作 |
| 网络 | 基础版离线，无后端、云存储和真实检测服务；不用 Supabase |
| 插件 | 优先引擎原生能力；当前不引入第三方付费插件或大型框架 |

技术依据按 2022.3 文档于 2026-10-18 复核：[ScriptableObject 数据资产](https://docs.unity3d.com/2022.3/Documentation/Manual/class-ScriptableObject.html)、[Android 权限](https://docs.unity3d.com/2022.3/Documentation/Manual/android-permissions-in-unity.html)、[persistentDataPath](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Application-persistentDataPath.html)。这些是同代 Unity API 参考，团结引擎具体兼容性与包版本以实际工程为准。迁移时复查已发现 AndroidPlayer、SDK、NDK、OpenJDK Java 程序与 Gradle 目录；打包前仍需核对配置与工具版本，文件存在不等于构建验收通过。

## 5. 分层与模块职责

```mermaid
flowchart TD
    View[UnityUI：页面 / 路由 / 媒体] --> UI[Presentation：纯 C# Presenter]
    UI --> App[应用层：调查用例与命令处理]
    App --> Domain[领域层：证据、权限、评分、结局规则]
    App --> Ports[接口：案件仓储、存档、媒体检测]
    Infra[基础设施：配置转换、JSON 文件、本地模拟检测] -.实现.-> Ports
    Data[ScriptableObject 案件与授权媒体] --> Infra
    Root[Main 场景 AppRoot] -.组装.-> View
    Root -.组装.-> UI
    Root -.组装.-> App
    Root -.组装.-> Infra
```

依赖方向：Domain、Application、Presentation 不引用 UnityEngine；Application 独占领域会话并编排用例；Infrastructure 实现仓储与检测接口；UnityUI 实现 View、导航和播放接口；AppRoot 在单一入口完成组装。Presenter 只提交用户意图、展示返回状态，不直接修改成绩或存档。详细程序集引用表以代码架构设计为准。

| 模块 | 建议职责 | 不应承担 |
| --- | --- | --- |
| CaseRepository | 读取目录、验证配置、生成独立运行数据 | 修改 ScriptableObject 记录玩家进度 |
| InvestigationService / InvestigationSession | Application 统一接收意图；Domain 会话封装生命周期、私有状态与事务 | 页面直接修改会话字段、文件读写、操纵 GameObject |
| EvidenceRules | 检查来源可用、按 evidenceId 收集去重、分类关键证据 | 每次点击都加分 |
| PermissionRules | 访问范围、决策状态、风险重算、越权事件 | 调用 Android 真权限接口 |
| DetectionService | 预设分析结果与演示延迟 | 声称调用了真实 AI 模型 |
| 核验规则 | 根据配置判断身份或来源核验是否可靠 | 启动真实电话或浏览器 |
| ScoringRules | 根据当前状态与历史越权事实计算三维分数及明细 | 累加过期权限奖励、按展示次数计分 |
| OutcomeResolver / 案件策略 | 即时失败、最终安全与失败规则 | 仅按总分推测是否安全 |
| ProgressService / IProgressRepository | 串行合并成绩、版本迁移、写入、恢复与损坏提示 | 各页面各自覆盖存档、存储真实个人媒体 |
| PageRouter / Presenter | 页面、返回栈、媒体释放和状态展示 | 将某一关剧情写死到公共页面 |

不使用跨项目的全局服务定位器。应用内事件只用于视图刷新；关键状态变更由会话直接处理，保证顺序可解释。页面离开时取消订阅；回到旧页面从会话读取快照，不能依赖“页面还活着”。

## 6. 数据模型与配置约束

以下是待实现的数据契约，不是现有类或代码。

| 数据 | 关键字段 | 约束 |
| --- | --- | --- |
| CaseDefinition | id、contentVersion、scoringRuleVersion、标题、案例类型、requiredSteps、消息、证据、权限、核验、结局规则 | id 稳定且唯一；配置只读 |
| MessageDefinition | id、消息类型、角色、正文、mediaId、evidenceIds、actionId | 支持六种消息；媒体与动作引用存在 |

| MediaDefinition | id、类型、文字稿 / 字幕、assetLedgerId | 纯 C# 定义仅存标识；实际 Unity 媒体引用留在资源索引，来源台账可追溯 |

| PermissionDefinition | id、用途、allowedScopesByIntent、acceptedDecisionsByIntent、scoreWeight、riskWeightsByIntentAndScope | 七类访问；用途按案例定义，案件三采用拍摄 / 指定照片 / 放弃功能；权限分合计 30 |
| VerificationOption | id、显示文字、reliable、反馈 | 案件一二含原联系方式；案件三为开发者与来源 |

| SessionState | sessionId、caseId、阶段、线索集合、featureIntent、权限决策、已读 / 已检测 / 核验状态、模拟安装状态、操作日志 | 权限决策为 Unreviewed / Denied / Allowed(scope)；记录核验“已选择”和“可靠性”两个字段；重开生成新 sessionId |
| ScoreEntry | ruleId、dimension、delta、reason、relatedItemId | 最终评分解释明细；一次性历史越权事实单独去重，不能重复计入总分 |
| CaseResult | resultId、caseId、contentVersion、scoringRuleVersion、三维分数、总分、风险、outcome、错误与建议 | 终局后冻结；成绩和复盘使用同一份结果 |

## 7. 状态与操作流程

调查步骤允许自由往返，不强制先点完所有聊天再查权限。使用“完成标记集合”表达调查进度，使用小型状态机表达生命周期，避免为每个页面创建一种业务状态。

```mermaid
stateDiagram-v2
    [*] --> Investigating: 配置加载并校验完成
    Investigating --> Investigating: 阅读 / 取证 / 检测 / 权限 / 核验
    Investigating --> Resolved: 即时危险行为
    Investigating --> Investigating: 普通提交缺少必要调查项
    Investigating --> Resolved: 提交并冻结安全或失败结果
    Investigating --> Aborted: 确认退出
    Resolved --> [*]
    Aborted --> [*]
```

保存使用独立的 Pending / Saving / Saved / Failed 状态，附着于冻结 resultId，不属于领域调查状态。页面导航、提交缺项反馈也各自处理。重试创建新的会话，旧会话不会从终局回到调查。

一次操作按顺序执行：校验会话与合法性 → 修改领域状态 → 记录首次越权等历史事实 → 重算当前风险 → 检查即时失败并冻结结果 → 返回一致快照。整个领域事务同步完成，不能向界面发布中间状态。若进入终局则拒绝后续业务操作，只允许展示、重试保存、返回或开启新会话。

媒体扫描属于调查中的子状态。扫描完成回调必须携带 sessionId 与任务标识；切关、重开或退出后旧回调失效。防止重复扫描奖励和连续点击重复结算。

提交前只检查必要操作已完成：背景已查看、至少有效收集一条线索、适用媒体已播放并检测、权限已逐项明确判断、已选择核验方式、已选择风险分类与处置。案件三通过 requiredSteps 排除聊天和检测。没有操作的项目列出缺项；不能要求答案正确后才让玩家提交。

证据不足四条时显示缺少数量及待调查来源，不公开未发现证据的标题和结论，并提供“继续取证 / 按现有证据提交”，不锁死提交。四条是每关必须提供的计分关键线索数量，不是预先保证玩家满分的门槛。可靠核验、正确分类、正确处置以及无未解除的危险状态共同决定安全结局；错误核验仍可提交并在复盘解释。课程要求的完整演示路线仍包含收齐证据和正确核验。

危险动作无须等待上述提交门槛，立即进入对应失败结局。错误分类或错误处置在调查完整后提交，也进入失败结局。

## 8. 评分、风险与结局

### 8.1 三项能力，共 100 分

| 能力 | 满分 | 算法 |
| --- | --- | --- |
| 识别与取证 | 40 | 四条关键证据各 10 分，按 evidenceId 首次有效收集计分；补充线索不额外加分 |
| 权限判断 | 30 | 最终决策与预期最小访问范围一致的项目权重之和，减去一次性越权操作扣分，最低 0 分 |
| 安全处置 | 30 | 可靠核验 10 分、风险分类正确 10 分、最终处置正确 10 分，三项独立保留；错误或未完成的项为 0 分，分别显示原因 |

总分为三个维度之和，范围 0 至 100。权限子项权重按案件配置，总和必须为 30；Unreviewed 不等于 Denied，未判断的项得 0 分且阻止普通提交。必要权限也可拒绝，但须选择放弃对应功能；允许时必须匹配用途和范围。

仅案件三明确选择拍摄、使用指定照片或放弃使用功能；案件一二使用各自配置的用途或固定上下文。拍摄路径可允许摄像头并拒绝其他访问；指定照片路径可允许选定照片并拒绝其他访问；放弃功能路径可全部拒绝。以上均为合法满分权限答案。改变用途后重新评价当前权限、风险与首次越权事件，已经记录的越权事件不能通过切换用途抹除。

失败结局不清空做对的分项。例如先正确核验、正确分类再错误转账，安全处置为 20 / 30；如果一开始就转账，未执行的核验与分类显示“未完成”，处置显示“错误”，均为 0。结果展示顺序为结局、原因、分数，不能用较高分数掩盖失败。

模拟授予某项非必要访问，首次对该项目记录权限维度扣 5 分；撤销后当前风险下降，历史错误记录与扣分仍保留；同一项目反复开关不能叠加奖励或重复扣分。计分原因包含规则、关联项目与分值。

分数表示能力表现，结局由明确安全规则决定。即使收齐证据后错误授权导致总分较高，结局仍是失败；界面须清晰显示失败原因，不能把“最高分”当作“已安全通关”。

### 8.2 当前隐私风险与案件风险

风险独立于得分，范围 0 至 100。每次访问决策改变后，根据当前允许范围重算，而非累计相加。

案件三建议风险权重：摄像头在拍摄用途下为 0、超出当前用途时为 10；仅指定照片在指定照片用途下为 0、超出当前用途时为 10；全部相册 20、麦克风 10、通讯录 20、短信 20、定位 15、后台运行 15。相册的“仅指定”与“全部”互斥；按当前用途与范围求和后限制在 0 至 100。其余案件也由配置提供用途 / 范围对应权重，使用相同上限。改变用途不会自动替玩家撤销授权，但会立即重算风险。

界面区分“当前隐私风险”和“案件风险”：前者随撤销而下降，后者展示诈骗、恶意安装等其他风险及已触发的严重事件。当前风险可显示低（0 至 19）、中（20 至 49）、高（50 至 100）；风险为 0 不代表对方身份可信或可以转账。曾经的危险操作仍在复盘中保留。

### 8.3 结果与复盘

结局值：Safe、ScamFailure、MalwareFailure、PrivacyFailure、JudgmentFailure。重试是新的会话，不覆盖之前的正确通关记录。复盘按错误操作逐条给出“做了什么 → 为什么有风险 → 正确做法”，并显示关键证据、三维得分、加扣分明细及模拟检测的局限。

## 9. 存档与异常恢复

基础版只承诺保存已结算成绩，不承诺恢复进行到一半的调查。退出未完成案件时提示“本次调查进度未保存”，再次进入从新会话开始。

每关在对应 scoringRuleVersion 下记录 highestTotalScore、highestSafeScore（未安全通关时为空）、hasSafeClear、lastResult，以及最多 10 条最近结果。hasSafeClear 只可由 Safe 结果置为真；失败不得清空已有安全通关。resultId 去重，重复保存不能重复计入历史；最高分聚合不随历史列表裁剪而丢失。内容版本、评分规则版本与存档结构版本分开，旧结果保留当时评分和解释。

写入流程：序列化到同目录临时文件 → 完整关闭文件 → 使用平台适用的替换方式更新主存档 → 保留上一份有效备份。读取校验 JSON、schemaVersion、范围和案例 ID；主文件损坏尝试备份，均无效则明确提示并提供新建存档选项，不静默覆盖。未知的新版本存档保留原文件并提示不兼容。

在结果生成后立即保存，不依赖应用退出回调；Android 进程可能直接被终止。应用级 ProgressService 串行合并待保存结果，避免不同页面或会话用旧快照覆盖新成绩。保存失败仍可看本次结算，但显示“成绩未保存”，提供重试；重试复用冻结的 CaseResult。文件保存属于内部学习进度，不需要申请共享存储权限。

## 10. 移动安全与素材约束

- 所有权限开关只改变 SessionState，不调用系统权限申请接口。
- 使用预置照片、音频与视频；摄像头、麦克风、通讯录、短信、位置均不实际访问。
- 对敏感来源、真人肖像、声音、字体和第三方素材逐项记录授权；未获授权的素材不能用于交付。
- 不在真实浏览器打开案件链接，不使用真实恶意 APK，不真实发起支付、通话和安装。链接显示虚构域名，安装包仅为元数据与模拟界面。
- 工程建立后检查最终合并的 AndroidManifest，而非只看手写清单；Unity 功能或插件可能自动带入权限。基础版不引入广告、统计或无关网络组件。
- 签名材料与令牌不进入 Git；APK 和工程压缩包按最终交付流程单独提供，仓库只保留可复现的工程与授权资源。
