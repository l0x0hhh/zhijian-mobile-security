## 1. 案件定义与豁免

| 字段 | 内容 |
| --- | --- |
| caseId | `photo-permission`，保持稳定 |
| 页面标题 | 证件照权限 |

### 隐私政策与声明原文

`photo-permission.policy.function`：“照片处理需要一张图片。你可以拍摄，也可以只选择一张现有照片。”

`photo-permission.policy.collection`：“为改进服务，我们可以读取通讯录、短信、位置和相册中的全部照片，并用于关联分析。”

`photo-permission.policy.background`：“即使退出编辑，也须允许持续后台运行；拒绝后将无法制作证件照。”

这些条款故意构成待审查的教学问题，不是真实服务条款、法律意见或对现有应用的指控。不增加“同意并继续”的默认全授权按钮，不让阅读政策自动代表同意。

### 当前风险与历史越权

| 当前允许项 | 与用途匹配时风险 | 超出当前用途时风险 |
| --- | --- | --- |
| 摄像头，仅使用时 | 拍摄：0 | 指定照片或放弃：10 |
| 相册，仅指定照片 | 指定照片：0 | 拍摄或放弃：10 |
| 相册，全部相册 | 无匹配用途 | 所有用途：20 |
| 麦克风 | 无匹配用途 | 10 |
| 通讯录 | 无匹配用途 | 20 |
| 短信 | 无匹配用途 | 20 |
| 定位 | 无匹配用途 | 15 |
| 后台运行 | 无匹配用途 | 15 |

拒绝或待判断时不表示已授予，当前风险贡献 0；待判断仍挡住普通提交。用途未选时，允许操作先提示“请先选择用途”，不生效、不记越权；查看声明和明确拒绝仍可进行。选择用途后再确认允许，不自动选用途或默认授权。这里只细化交互前置条件，不新增一种评分状态。

按当前允许项求和后限制在 0–100；低 0–19、中 20–49、高 50–100。风险是教学权重，不是真实隐私泄露概率。改变用途立即重算，但不自动撤销原授权；已合法授权的项目因新用途变为非必要时，也记录该项目首次越权。每项目首次越权扣 5，只记一次；从指定照片改全部相册、反复切换或撤销后再允许不重复扣同一项目。

示例：指定照片用途下仅允许选定照片，风险 0；改成全部相册为 20；再撤销为 0，历史越权扣分仍保留。拍摄用途仅允许摄像头时风险 0；切换到放弃功能却未撤销摄像头，风险 10，并产生摄像头首次越权。

## 5. 核验、分类与处置选项

### 5.1 来源核验（不是回拨身份）

| optionId | 选项 | 可靠性 / 反馈 |
| --- | --- | --- |
| `photo-permission.verify.independent` | 核对开发者与独立分发来源 | 可靠方法；本地对照资料反馈“没有找到与发布者相符的主体和可信发布记录，来源仍无法核实。”；表示方法可靠，不表示应用可靠 |
| `photo-permission.verify.self-description` | 相信应用里的“安全可靠”说明 | 不可靠；“这是应用自己的说法，缺少独立依据。” |
| `photo-permission.verify.download-count` | 看下载量就判断可信 | 不可靠；“下载量不能证明访问必要或来源可信。” |
| `photo-permission.verify.privacy-title` | 有隐私政策就相信 | 不可靠；“需要看条款内容，标题不能证明收集合理。” |

查看详情和独立目录不自动完成可靠核验，须选择方式并查看反馈。可靠核验 10 分；不要求联系任何虚构人物或读取真实通讯录。

### 5.2 风险分类

| optionId | 选项 | 判定 / 反馈 |
| --- | --- | --- |
| `photo-permission.class.excess-permission` | 过度授权与隐私风险 | 正确；“多项收集与制作一张照片无关。” |
| `photo-permission.class.normal` | 正常照片处理所需 | 错误；“照片功能不能解释短信、通讯录和持续后台要求。” |
| `photo-permission.class.storage-only` | 只是照片存储空间不足 | 错误；“本案问题是访问范围和用途，不是存储容量。” |

正确分类 10 分。

### 5.3 最终处置

| optionId | 选项 | 判定 / 行为 |
| --- | --- | --- |
| `photo-permission.disposition.reject` | 按需审查后，拒绝使用并留证 | 正确处置，10 分；记录拒绝使用该不可信应用，不实际导出照片或执行系统卸载；保留玩家已判断的权限作为本次审查答案，不自动改成全拒绝 |
| `photo-permission.disposition.keep-using` | 保留当前授权，继续使用 | 错误；不强制扩大权限，普通提交根据当前权限及判断产生失败 |
| `photo-permission.disposition.trust-policy` | 有政策就接受并继续 | 错误；不替玩家完成来源核验，普通提交进入失败复盘 |

正确处置与权限分分开：拍摄/指定照片用途的必要最小授权可作为审查练习答案保留，最后仍应拒绝使用不可信应用；界面需说明“本次为权限判断练习，没有真实授权”。选择放弃功能时则应七项全拒绝。处置不偷偷消除历史，也不补齐未收集证据。

## 7. 即时与最终安全/失败路径

**即时失败：不适用。** 允许越权、扩大相册或改变用途只更新当前风险与历史扣分，不立即终止；可在提交前撤销。案件三不套用安装加授权规则，也不要求模拟安装。

普通提交先检查适用必做项和少证据确认，再按以下优先级冻结结果：

1. 当前允许任一非必要项目、摄像头/指定照片超出当前用途，或相册为全部 → `PrivacyFailure`。即使其他答案全对，也优先显示该结局。
2. 无上述授权，但核验不可靠、分类错误、处置错误，或必要访问与所选功能不匹配 → `JudgmentFailure`。
3. 当前权限完全符合所选用途、核验可靠、分类正确且拒绝使用并留证 → `Safe`。

当前风险 0 不代表判断全对。历史越权已撤销且当前答案满足安全要求时，可以 Safe，但保留扣分。失败描述为“模拟隐私风险”，不声称真实照片或通讯录已经泄露。结果冻结后不能靠撤销授权改写，仅重开新会话。

| 路线 | 操作序列 | 静态预期 |
| --- | --- | --- |
| 拍摄安全 | 查看详情/政策 → 收四证据 → 选拍摄 → 摄像头仅使用时允许，其余拒绝 → 独立核验 → 正确分类 → 拒绝使用并留证 → 提交 | Safe，100；无聊天、播放或检测 |
| 指定照片安全 | 同上，选指定照片，仅指定照片允许，其余拒绝 | Safe，100；不要求同时允许摄像头 |
| 放弃功能安全 | 同上，选放弃功能，七项拒绝 | Safe，100；不强迫授权 |
| 全部相册失败 | 指定照片路线，改成全部相册，其他操作和答案正确 → 提交 | PrivacyFailure，风险 20；40 + (26 − 5) + 30 = 91 |
| 非必要访问失败 | 放弃用途，允许短信、其余拒绝，其他全部正确 → 提交 | PrivacyFailure，风险 20；40 + (25 − 5) + 30 = 90 |
| 用途变化失败 | 拍摄且摄像头允许 → 改放弃功能但不撤销摄像头，其他全部正确 → 提交 | PrivacyFailure，风险 10；40 + (26 − 5) + 30 = 91 |
| 撤销后补救 | 指定照片用途曾给全部相册 → 改回仅指定照片，其他全部正确 → 提交 | Safe，风险 0；40 + (30 − 5) + 30 = 95 |
| 无越权但功能不符 | 选拍摄、七项全拒绝，其他全部正确 → 提交 | JudgmentFailure，风险 0；40 + 26 + 30 = 96；提示改放弃用途或按需判断 |
| 错误核验 | 最小授权和其他操作正确，核验仅相信自述 → 提交 | JudgmentFailure，40 + 30 + 20 = 90 |
| 少证据安全 | 合法权限、其他答案均正确，仅收一条关键证据 → 确认提交 | Safe，10 + 30 + 30 = 70 |
