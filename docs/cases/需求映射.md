## 5. 共用字段与规则接入清单

以下是内容语义到现有架构契约的映射，不要求新增公共类型，不保证字段名与未来 API 逐字相同。ID 与显示顺序、标题解耦；脚本中 `source.x` 等缩写均属于当前 caseId，映射时展开为该案完整 ID。

| 契约 | 应提供的内容 | 本稿来源 / 接入检查 |
| --- | --- | --- |
| CaseDefinition | caseId、标题、类型、版本、requiredSteps、policyId 引用 | 各案第 1 节及提交/结局节；版本和已注册策略 ID 由主窗口分配，不杜撰现成 API |
| MessageDefinition | messageId、类型、roleId、正文、mediaId/sourceId/actionId | 一二消息表；三为空。全局六种消息都有适用内容 |
| MediaDefinition | mediaId、类型、文字稿/字幕、实际素材引用及 assetLedgerId | 一二媒体节和素材待办；实际文件/台账 ID 未落实前不把案件标成可用 |
| EvidenceDefinition | evidenceId、来源集合、解释、有效触发、isKey、scoreWeight | 四证据表；每案四 key × 10；会议敏感请求是 0 分补充，不新增第五项计分证据 |
| DetectionProfile | mediaId、指标、状态、依据、风险等级、模拟标识与局限 | 一二三指标；三不启用。可重复分析但不重复得分 |
| PermissionDefinition | permissionId、固定用途或三意图、允许范围、正确决策、分值、按用途/范围风险 | 每案权限表；初始待判断；后台能力注明模拟语义 |
| VerificationOption | optionId、短标签、reliable、反馈、本地结果来源 | 核验表；可靠方法不等于应用/人物可信，三案均含错误方法 |
| 分类/DispositionOption | optionId、风险类别、显示文案、动作、正误、即时性 | 分类与处置表；选择与执行危险动作区分，不能靠普通提交门槛屏蔽即时后果 |
| requiredSteps | 适用背景、有效线索、媒体、权限、核验、分类与处置 | 一二要求实际播放及检测；三不含聊天/播放/检测，增加用途选择与详情/政策查看 |
| Result / ScoreEntry | 实际原因、三维分值、一次性越权、结局、错误与建议 | 评分和复盘节；终局只冻结一次，不用总分判断 Safe，保存状态独立 |

三案权限项目顺序统一：camera、photos、microphone、contacts、sms、location、background。项目 ID 以 caseId 命名空间展开；相册只有一个项目，范围互斥。分值 4 + 4 + 4 + 5 + 5 + 4 + 4 = 30。

权限分 = 最终正确项目权重之和 − 首次越权项目数 × 5，最低 0。当前风险按当前范围重算并封顶 100，撤销不抹除历史。三案评分独立保持 40/30/30；核验、分类、处置各 10；已答对项不因失败清空。待判断不等于拒绝，未完成与答错分别解释。

只在普通提交时检查适用操作；错误答案允许提交；证据不足四条时需确认，确认只展示数量和待查看来源，不泄露未发现标题。即时转账和安装敏感授权组合优先于普通门槛。案件三仅在最终提交检查隐私失败，没有即时失败。冻结后不接受撤销、移除、旧扫描回调或重复提交改变结果。

## 7. UI 文案与未验证事项

- 手机端标题直接说明任务或事实，不用宣传口号、装饰英文或重复标签；结果先显示具体结局，再显示分数。
- 消息、指标、反馈和复盘分别承担不同信息，不在同一屏用标题/胶囊/描述重复一句话。长脚本表格供实施者阅读，不整页搬进手机。
- 普通文字按 UI 规范字号；政策与聊天可滚动，底部操作可达；权限用列表加选择层，相册明确指定/全部范围；状态配文字，不只用颜色。
- 先播放/打开媒体，再从菜单或详情取证；长按是补充。缺项提示只列适用操作，少证据提示不提前给答案。
- 只有文字核对与静态推演。尚未验证：运行时字段映射、Unity 交互、字幕时序、实际媒体异常可见性、字体、小屏/安全区、音视频中断、离线运行、Manifest、成绩存档和 Android 真机。

主窗口接入顺序：分配版本/策略引用 → 将内容映射为只读定义 → 落实实际媒体与可追溯授权 → 校验来源/证据可达与四 key/30 权限权重 → 接入页面和普通/即时终局 → 后续按验收计划实际执行。当前文档不代表任一步已经运行通过。
