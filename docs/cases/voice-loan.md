# 语音借款

## 1. 案件定义与边界

| 字段 | 内容 |
| --- | --- |
| caseId | `voice-loan`，不随标题与排序改变 |
| 页面标题 | 语音借款 |
| 选关简述 | 好友换了账号，发来语音催你借钱。 |
| 玩家任务 | 查清身份、审查验证助手，决定是否转账。 |
| 固定用途 | 核实借款请求；验证助手没有必要访问设备数据 |
| 入口 | 调查手机 → 聊天；安全中心可直接审查权限和核验 |
| 内容状态 | 脚本完成；未制成运行时配置，未生成音视频或图片 |
| 版本 | 内容稿 1；接入时由主窗口分配 contentVersion / scoringRuleVersion |

剧情、姓名、账号、金额和来源页面均为虚构。所有联系、链接、收款及权限行为只改变案例内状态。下列 ID 是内容定位键，不是已实现的公共 API。评分依据既有设计，课程依据与差异见[需求映射](需求映射.md)。

## 2. 角色与消息顺序

| 角色 ID | 显示名 | 设定 |
| --- | --- | --- |
| `voice-loan.role.player` | 我 | 收到借款请求的学生 |
| `voice-loan.role.sender` | 林澈（新账号） | 冒充者使用的虚构身份；聊天首屏不揭示冒充结论 |
| `voice-loan.role.friend` | 林澈（原联系人） | 案例通讯录中的既有联系人；号码只显示“原号码”，不使用真实电话号码 |
| `voice-loan.role.helper` | 转账验证助手 | 新账号推荐的虚构权限诱导页 |

基础消息按 01 至 06 排列，进入聊天即可逐条查看，不以正确答案解锁下一条。背景查看标记：基础消息全部进入可见区或逐条打开详情；不以收集证据代替阅读。核验回复与追问分支不属于背景必读项。

| messageId | 类型 / 发送者 | 手机端正文或标题 | 主点击 / 来源 |
| --- | --- | --- | --- |
| `voice-loan.msg.01` | 文字 / 新账号 | 我是林澈，原来的号登不上了。先加这个。 | 消息菜单；账号资料 `voice-loan.source.account` 显示“本次新添加，无历史聊天” |
| `voice-loan.msg.02` | 语音 / 新账号 | 语音 14 秒；文字稿随播放器可查看 | 播放 `voice-loan.media.request` |
| `voice-loan.msg.03` | 图片 / 新账号 | 先转 800 元到这个收款码。 | 打开 `voice-loan.media.payee`；图内为“收款人：杜禾 / 金额：800 元 / 教学收款码”，无可扫描真实二维码 |
| `voice-loan.msg.04` | 文字 / 新账号 | 别回拨原号码，我现在接不了。转完发截图。 | 消息详情；可收集拒绝原号码回拨的线索 |
| `voice-loan.msg.05` | 链接 / 新账号 | 转账前先打开验证助手。 | 本地模拟页 `voice-loan.source.helper`；展示地址 `https://check-transfer.invalid/verify`，不发起网络请求 |
| `voice-loan.msg.06` | 文字 / 我 | 我先确认一下。 | 固定剧情回复，不替玩家执行核验或安全处置 |

文字/图片消息点选后通过菜单取证，长按是补充。语音主点击先播放；播放器、消息菜单和顶栏线索入口提供取证动作，不让取证抢占播放。底部提示：“点选消息可查看操作。”主任务入口：“分析材料”“核验身份”。“立即转账”在聊天操作入口始终可达。

可选追问 `voice-loan.action.ask-current` 的回复：“声音都发了，先帮我转一下。”只追加补充对话，不产生可靠核验，不清除缺项。

## 3. 媒体文字稿与教学检测

### 3.1 语音 `voice-loan.media.request`

目标约 14 秒；时间段为制作指导，正式录音后按真实时长调整字幕和停顿位置。本轮未录制，不声称已有可播放素材。

| 时间 | 文字稿 / 制作说明 |
| --- | --- |
| 00:00–00:04.8 | “是我，林澈。我这边急用八百块。” |
| 00:04.8–00:05.5 | 句中出现不自然的停顿，保留轻微底噪衔接变化；不以夸张音效吓人 |
| 00:05.5–00:10.0 | “收款码发你了，你先转过去。” |
| 00:10.0–00:14.0 | “现在不方便接电话，晚点跟你说。” |

文字稿不另写“这是克隆语音”等答案。图片的替代文字：“教学收款信息：杜禾，800 元。”图片打开后可阅读收款人，不依赖二维码或小字辨认。

### 3.2 模拟检测 `voice-loan.detection.request`

页面持续显示：“教学模拟：以下为预设结果，不是真实鉴定。”风险等级表示本案教学材料的预设媒体风险，不等于当前隐私风险，也不表示任何真人被鉴定。

| 指标 | 预设状态 | 短说明 |
| --- | --- | --- |
| 语音韵律 | 异常 | 两段语气衔接生硬。 |
| 停顿衔接 | 异常 | 句中停顿不自然。 |
| 背景噪声 | 异常 | 停顿前后底噪有变化。 |

标题：“发现 3 处异常”；媒体风险：“高（教学预设）”。局限：“异常只能辅助判断，请通过原联系方式核实。”不输出真假概率、置信度、鉴定报告编号或真实模型名称。重新分析返回同一预设结果；完成检测本身不另外加分。

媒体缺失或播放失败：“语音未能播放，请重试。”扫描失败：“分析未完成，请重试。”文字稿可阅读，但不能冒充播放成功，也不能用静态稿替代正式验收的播放或检测完成标记。

## 5. 权限、用途、范围与正确选择

“转账验证助手”是顶层设计补充的通用权限练习，不是课程要求必须安装的借款工具。固定用途：“核实借款请求”；不设置拍摄/指定照片/放弃功能选项。这一用途不需要助手获取下列访问能力，正确选择全部为拒绝。打开权限声明即可审查，无需安装。

七项初始均为“待判断”；拒绝必须由玩家明确选择。所有“允许”仅为本地模拟。相册范围互斥，后台运行是教学访问能力类别，不宣称对应统一 Android 危险权限。

| 权限 ID 后缀（前缀 `voice-loan.permission.`） | 显示名 / 诱导用途 | 可选范围 | 正确选择 / 权重 | 允许时的当前风险权重 |
| --- | --- | --- | --- | --- |
| `camera` | 摄像头 / “拍照验身份” | 拒绝；仅使用时允许 | 拒绝 / 4 | 10 |
| `photos` | 相册 / “上传支付截图” | 拒绝；仅指定照片；全部相册 | 拒绝 / 4 | 指定 10；全部 20 |
| `microphone` | 麦克风 / “声音验证” | 拒绝；仅使用时允许 | 拒绝 / 4 | 10 |
| `contacts` | 通讯录 / “匹配好友” | 拒绝；允许读取 | 拒绝 / 5 | 20 |
| `sms` | 短信 / “自动读验证码” | 拒绝；允许读取 | 拒绝 / 5 | 20 |
| `location` | 定位 / “确认所在地区” | 拒绝；仅使用时允许 | 拒绝 / 4 | 15 |
| `background` | 后台运行 / “持续验证” | 拒绝；允许后台运行 | 拒绝 / 4 | 15 |

权限权重合计 30。当前隐私风险等于当前允许项权重之和，最高 100；全部拒绝为 0。风险等级采用既有设计的低 0–19、中 20–49、高 50–100。首次允许某个非必要项目记录该项目一次越权，权限分扣 5；反复允许、扩大相册范围或撤销后重开不对同一项目重复扣 5。撤销降低当前风险，不抹除历史扣分。当前风险为 0 不代表借款请求可信。

反馈：“这项访问与核实借款无关。”撤销反馈：“当前风险已下降，先前越权仍会记录。”本案的权限风险权重为内容配置建议，课程未规定具体数值；由主窗口接入时核对。

## 6. 核验、分类与处置

### 6.1 核验选项

| optionId | 选项 | 可靠性与即时反馈 |
| --- | --- | --- |
| `voice-loan.verify.original` | 通过原联系方式联系本人 | 可靠；虚拟原联系人回复：“我没有借钱，也没换账号。先别转，保留消息。” |
| `voice-loan.verify.current-chat` | 在当前聊天里追问 | 不可靠；“仍由同一个账号回答，身份没有独立确认。” |
| `voice-loan.verify.new-number` | 联系对方新发的号码 | 不可靠；“号码也由对方提供，不能独立核实。” |
| `voice-loan.verify.voice-only` | 听起来像本人就相信 | 不可靠；“声音相似不能确认身份。” |

只要选择并查看核验反馈，即完成“已选择核验方式”；错误选项不阻止提交。可在终局前改选；评分按最终有效选择。可靠核验 10 分。

### 6.2 风险分类

| optionId | 选项 | 正误与反馈 |
| --- | --- | --- |
| `voice-loan.class.impersonation` | 冒充身份诈骗 | 正确；“新账号、收款人和回拨要求存在矛盾。” |
| `voice-loan.class.normal` | 正常好友借款 | 错误；“尚未通过独立渠道确认借款人。” |
| `voice-loan.class.permission-only` | 只有权限问题 | 错误；“助手越权之外，还有冒充借款风险。” |

正确分类 10 分；不因先做检测而自动选中答案。

### 6.3 最终处置（四选一）

| optionId | 选项 | 行为与反馈 |
| --- | --- | --- |
| `voice-loan.disposition.verify-refuse` | 原联系方式核实，拒绝转账并留证 | 正确处置；若还未选可靠核验，提示“仍需独立核实身份”，不暗中补做核验；普通提交时允许错误核验进入失败复盘 |
| `voice-loan.disposition.transfer` | 立即转账 | 危险即时动作；聊天或提交页一旦执行，立刻 ScamFailure，不等其他步骤 |
| `voice-loan.disposition.keep-asking` | 继续向当前账号追问 | 非安全处置；追加追问分支仍可调查，普通提交选择此项则 JudgmentFailure |
| `voice-loan.disposition.follow-link` | 按对方链接做核验 | 非安全处置；调查时可查看本地诱导页，不能据此完成可靠核验；普通提交选择此项则 JudgmentFailure |

处置分独立 10 分；“查看链接”“试着追问”与把它选作最终处置分开记录，浏览本地页面本身不终局。正确选项中的“留证”保留本次已收集证据，不自动补齐四条。

## 7. 普通提交必做项与缺项提示

| 操作项 | 完成条件 | 未完成提示 |
| --- | --- | --- |
| 查看背景 | 基础消息 01–06 已查看 | 请先查看聊天背景。 |
| 有效取证 | 至少有效收集四条关键证据中的一条 | 请先收集一条有效线索。 |
| 播放媒体 | `media.request` 成功播放完成 | 请先播放语音。 |
| 模拟检测 | `detection.request` 完成 | 请先完成语音分析。 |
| 权限判断 | 七项全部明确拒绝或允许某范围 | 还有 {数量} 项访问待判断。 |
| 核验 | 已选择一项并查看反馈 | 请选择核验方式。 |
| 分类与处置 | 两项均有选择 | 请选择风险类型和处置。 |

不以“全部答对”“收齐四证据”“权限风险为 0”作为普通提交门槛。已有 1–3 条证据且其他操作完成时，提示“还少 {数量} 条关键线索。可继续查看聊天、媒体或账号资料。”按钮：“继续取证”“按现有证据提交”。该提示不透露未发现证据的具体标题。

即时转账不受此表限制。未收集任何有效证据时，普通提交仍被阻止，不以确认按钮绕过。

## 8. 即时与最终路径

即时规则优先：执行 `disposition.transfer` → 先记录转账错误，立即冻结 `ScamFailure` 与当时分数；未完成项标“未完成”，做错项标“错误”。冻结后不能撤销转账或继续调查改变成绩。

普通提交在必做项完成及少证据确认后判定：可靠核验、分类正确、正确处置、当前七项全拒绝 → `Safe`；其他情况 → `JudgmentFailure`，逐项解释实际错误。权限首次越权后撤销可安全结案，但保留扣分。当前有非必要授权时不算安全；不套用案件三的隐私泄露专属结局。本案助手不增加未经设计的恶意安装即时规则。

| 路线 | 操作序列 | 预期结局 |
| --- | --- | --- |
| 完整安全 | 查看背景 → 成功播放 → 收齐四证据 → 模拟检测 → 七项拒绝 → 原联系方式核验 → 冒充诈骗 → 核实、拒绝转账并留证 → 提交 | Safe，100 分 |
| 少证据安全 | 同上，仅收一条关键证据 → 确认按现有证据提交 | Safe，70 分；取证不完整在复盘提醒 |
| 最短即时失败 | 进入聊天 → 立即转账 | ScamFailure，0 分；核验分类等为未完成 |
| 高分即时失败 | 四证据、七项拒绝、可靠核验、正确分类均完成 → 立即转账 | ScamFailure，40 + 30 + 20 = 90；处置错误 |
| 普通判断失败 | 其他必做项完成、四证据七拒绝，选择当前账号追问作为核验，分类/处置正确 → 提交 | JudgmentFailure，40 + 30 + 20 = 90 |
| 越权后补救 | 完整安全流程中曾允许短信再拒绝，其余正确 → 提交 | Safe，40 + 25 + 30 = 95；当前风险 0，保留一次越权 |

以上为静态规则推演，未在程序中执行。

## 9. 评分解释与手机复盘文案

三项能力：识别与取证 40，权限判断 30，安全处置 30。权限分 = 最终判断正确项目的权重合计 − 首次越权项目数 × 5，最低为 0；待判断项不算拒绝、不得分。安全处置 = 可靠核验、正确分类、正确处置各 10，分别保留。总分与结局独立，检测/浏览/重复取证不额外加分。

| 场景 / 原因 ID | 结果或复盘短文 |
| --- | --- |
| `voice-loan.result.safe` | 标题“已通过原联系方式核实”；原因“本人否认借款，你拒绝了转账并保留证据。” |
| `voice-loan.result.scam` | 标题“仍然执行了转账”；原因“你把钱转给了未核实的收款人。” |
| `voice-loan.result.judgment` | 标题“这次处理仍有风险”；原因按实际错误显示，不提前宣称转账或泄露已经发生 |
| `voice-loan.review.verify` | “当前账号的回答不能独立证实身份。下次通过原联系方式确认。” |
| `voice-loan.review.classification` | “你忽略了冒充借款的线索。把账号、收款人和回拨要求放在一起判断。” |
| `voice-loan.review.permission` | “验证助手索取了无关访问。核实借款不需要这些授权。” |
| `voice-loan.review.disposition` | “追问或对方给的链接不能完成核验。确认本人后再决定，并保留现有证据。” |
