## 公开 API 与所有权

命名空间按目录分为 `Zhijian.Domain.Cases/Sessions/Rules/Results/Outcomes`。仅引用 `System` 和同层 Domain 类型，无引擎引用、第三方包、文件 IO、网络或真实系统权限访问。

| API | 使用契约 |
| --- | --- |
| `CaseDefinition(...)` | 构造字段见下表；所有集合及嵌套定义深度复制，输出为只读集合。允许保留非法配置值供校验器汇总 |
| `CaseDefinitionValidator.Validate(definition, resolver)` | 返回只读 `ConfigurationError` 列表，包含 `Code/ItemId/Message`；不启动案件 |
| `CaseDefinitionValidator.ValidateCatalog(definitions, resolver)` | 聚合各案问题，并检查目录为空及重复 caseId |
| `OutcomeResolver(IEnumerable<ICaseOutcomePolicy>)` | 按 policyId 显式注册，拒绝空项/重复策略；`CreateDefault()` 是注册三案的便捷方法 |
| `ICaseOutcomePolicy` | `PolicyId/CaseKind`；`EvaluateImmediate(state)` 可返回 null，`EvaluateFinal(state)` 必须返回 `OutcomeDecision` |
| `OutcomeResolver.IsRegistered/EvaluateImmediate/EvaluateFinal` | 查询匹配的策略；最终评估仍优先检查即时危险。评估本身不替代提交门槛、不修改会话 |
| `InvestigationSession(definition, resolver)` | 再次校验配置；无效时抛含诊断的 ArgumentException；每次创建生成新 sessionId |
| `CaptureState()` | 返回当前 revision 的独立只读副本，不返回可写实体集合 |
| `ViewSource(sourceId)`、`CollectEvidence(evidenceId)` | 查看来源、统一取证；无效来源不能收集，重复收集返回 AlreadyApplied |
| `SelectFeatureIntent(intentId)`、`SetPermission(permissionId, decision)` | 用途改变不自动撤销权限；提交每个权限新选择后重新检查越权与当前风险 |
| `SelectVerification/SelectRisk/SelectDisposition(optionId)` | 选择配置中真实存在的选项；错误选项可选择，立即转账选择后会同步结算 |
| `SetInstallation(SimulatedInstallState)` | 仅会议案适用；NotInstalled/Downloading/Downloaded/Installed 为模拟状态，所有方向变更都检查即时组合风险 |
| `BeginPlayback/CompletePlayback/CancelPlayback` | 参数为 sessionId、mediaId、requestId；Complete 另有 succeeded。仅成功回调标记播放完成 |
| `BeginDetection/CompleteDetection/CancelDetection` | 参数同播放；只接受有预设检测指标的媒体，保留此前成功结果，不自动收集证据 |
| `Submit(expectedRevision, confirmMissingEvidence = false)` | 缺必做项不结算；少于四条关键证据需玩家确认当前 revision；普通提交不检查答案必须正确 |
| `Abort()` | 转为 Aborted，不生成结果；后续动作均拒绝，重开须 new 新会话 |
| `EvidenceRules.CanCollect(state, evidenceId, out reasonId)` | 只判断属于本案及来源可用，去重由会话的 evidenceId 集合负责 |
| `PermissionRules.IsAllowedScopeValid/IsExpectedDecision/IsOverreach` | 分别判断范围合法、当前用途答案、当前允许是否越权 |
| `PermissionRules.CalculateRisk(definition, intentId, decisions)` | 根据当前允许范围重新求和并限制在 0～100，不累计点击次数 |
| `ScoringRules.Calculate(state)` | 返回只读 ScoreBreakdown：EvidenceScore/PermissionScore/DispositionScore/Total/Entries |
| `SubmissionValidator.Validate(state)` | 返回 IsReady/MissingRequirements/MissingKeyEvidenceCount/PendingSourceIds |
| `InvestigationSession.Result` | 终局前为 null；终局后为唯一 CaseResult，可复用保存，不能用重试保存创建新结果 |

`SessionCommandResult` 包含 `Status/ReasonId/Revision/Result` 和提交提示字段。Status 包括 Accepted、AlreadyApplied、InvalidAction、SessionClosed、StaleSession、StaleRequest、MissingRequirements、ConfirmationRequired、StaleRevision。无效、重复、缺项或待确认操作不增加 revision。

会话不含事件或 await。Application 必须在同一串行用例入口调用，校验普通用户命令的当前 sessionId，避免重入；媒体回调额外由 Domain 校验 sessionId 与 requestId。调用后再读取快照，不能发布事务中间状态。Domain 不创建 Application 的 SessionSnapshot 或保存状态。

## 配置字段与校验边界

`CaseDefinition` 构造参数按顺序为：

| 字段 | 含义 |
| --- | --- |
| id/contentVersion/scoringRuleVersion/title/kind/policyId | 稳定 ID、两个正整数版本、标题、案件类型及策略 |
| requiredSteps/sources/messages/media/evidence | 必做操作、来源、消息、媒体与证据 |
| permissions/featureIntents/defaultFeatureIntentId | 七类访问、用途列表及默认上下文 |
| verificationOptions/riskOptions/dispositionOptions/supportedOutcomes | 核验、分类、处置选项与可产生结局 |

策略 ID：`voice-loan` → VoiceLoan、`face-meeting` → FaceMeeting、`photo-permission` → PhotoPermission。caseId 与 policyId 分开存储；当前三案内容应使用任务表规定的同名稳定 caseId。

证件照用途固定为 `FeatureIntentIds.TakePhoto`（`take-photo`）、`SelectedPhoto`（`selected-photo`）、`Abandon`（`abandon`），defaultFeatureIntentId 必须为 null；用户先主动选用途，再判断权限。语音及会议案由配置提供默认用途上下文。

- `EvidenceDefinition(id, sourceId, title, explanation, isKey, scoreWeight)`：恰好四条关键证据，每条 10 分；补充证据为 0 分。
- `PermissionDefinition(id, purpose, category, scoreWeight, scopes, intentRules)`：Camera/Photos/Microphone/Contacts/Sms/Location/BackgroundActivity 各一项，权重合计 30。后台运行只是教学能力类别。
- `PermissionIntentRule(intentId, allowedScopes, acceptsDenied, riskWeights)`：allowedScopes 表示该用途的正确最小范围；界面可选范围由 PermissionDefinition.Scopes 提供，两者含义不同。
- `PermissionDecision.Unreviewed/Denied/Allow(scope)`：未判断不等于拒绝；Allow(None) 或未知枚举会抛参数异常。会话不接受把已判断权限写回 Unreviewed。
- 相册 Scopes 必须为 SelectedPhotos 与 AllPhotos；其余访问为 Full。每项权限每个用途恰好一条规则，风险表完整覆盖可选范围。正确必要范围风险为 0，越权范围为正数并不超过 100。
- 证件照拍摄用途只接受摄像头 Full；指定照片用途只接受照片 SelectedPhotos；放弃功能全拒绝。其他类别在上述用途均拒绝。必要访问的拒绝不计该项正确权重，选择 Abandon 后全拒绝才是完整满分权限答案。
- 会议案短信、通讯录在所有用途下都必须以拒绝为正确答案。其他案件风险数值由配置提供，不把证件照建议权重写死到规则。
- 权限权重可采用摄像头/相册各 5、其余各 4（总 30），这只是内容映射示例，未生成运行时配置。

来源使用 `SourceDefinition(id, kind, requiredForBackground, mediaId = null)`。直接阅读来源由 ViewSource 标记；Media 与 Detection 来源不能被 ViewSource 伪造，须由相应成功回调解锁。Verification 来源取证还要求已选择核验。消息来源须有对应 MessageDefinition，消息证据须有对应取证引用；媒体/检测来源须有真实存在的媒体 ID 和适用指标。

背景必读来源必须可直接阅读。证件照必须含必读 AppDetails 与 PrivacyPolicy，不能配聊天或音视频/检测门槛；可以引用预置图片。语音和会议案必须有聊天/背景入口、音视频消息、播放和检测步骤。语音检测 2～4 项；会议视频包含 AudioVideoSync、FaceEdges、Lighting。音视频须有文字稿/字幕，媒体须有素材台账 ID 和可达引用。

核验必须有可靠与不可靠选项及反馈；分类与处置必须有正确选项。正确处置语义依次是 RefuseTransferAndPreserve、RejectInstallAndReport、RefuseUntrustedApp。语音必须提供规定的四类处置；只有立即转账标记 IsImmediateFailure。SupportedOutcomes 须包含 Safe、本案特定失败和 JudgmentFailure，避免普通错答在终局时落入未声明结局。

校验器聚合空元素、重复/空白 ID、未知枚举、引用、用途、范围、权重、步骤和策略问题。空元素保留后报错，不被静默丢弃；权重合计使用 long，避免无效超大权重导致 Sum(int) 溢出。安全处置分固定为核验/分类/处置各 10，总 30，不给处置选项设计可叠加权重。

结构校验不读取素材台账文件，不证明素材已授权、媒体可播放、原联系方式文案确实可靠或页面入口实际可达；这些仍由内容/资源适配与人工验收负责。

## 关键边界静态推演

计分公式：`E = 已收集关键证据权重之和`；`P = max(0, 当前正确权限权重和 - 5 × 不同历史越权项目数)`；`S = 可靠核验10 + 正确分类10 + 正确处置10`。不把历史扣分账本再次加到已计算的结果里。

| 输入/操作序列 | 静态预期 |
| --- | --- |
| 不查看来源直接取证 | InvalidAction/evidence.source-unavailable，无线索与分数变化 |
| 同一证据重复点击、长按或检测后重新收集 | 集合只有一个 evidenceId，只计首次有效收集 |
| 收集补充线索 | 可以入栏，证据维度仍不超过 40 |
| 初始权限看起来关闭但未操作 | 仍是 Unreviewed，0 分且普通提交列出缺项 |
| 背景/有效证据/适用媒体/权限/核验/分类/处置任一未完成 | MissingRequirements，不冻结结果；即时危险仍可先失败 |
| 只收一条有效证据，其余操作完成且答案正确 | 先提示缺三条关键证据；确认当前 revision 后可 Safe，证据仅 10 分 |
| 核验方法不可靠，但所有操作完成 | 可以提交；核验为错误而不是未完成，最终 JudgmentFailure，其余正确分保留 |
| 四证据40、权限30、可靠核验10、分类正确10，然后立即转账 | ScamFailure，总 90，处置0；高分不会覆盖失败 |
| 初始直接立即转账 | ScamFailure，未做核验/分类记未完成，错误处置记错误，总分0 |
| 允许越权→拒绝→再次允许→再次拒绝 | 当前风险随当前授权下降；同一项目历史仅一次 -5，无反复开关奖励 |
| 指定照片用途授权 SelectedPhotos→改为 Abandon | 不自动撤销照片；立即产生该项目首次越权、重算风险；photo 暂不终局 |
| 改回指定照片用途，再次改 Abandon | 已记录的照片越权不消失也不重复扣分 |
| 指定照片改成 AllPhotos | 相同项目扩大范围，风险上升，该项目只记一次越权；最终仍允许则 PrivacyFailure |
| 相机拍摄、指定照片、放弃功能三条路径 | 分别允许相机、允许指定照片、全部拒绝，均可取得权限满分；不要求相机与照片同时授予 |
| 会议仅下载/安装、短信通讯录未允许 | 不触发即时 MalwareFailure，动作日志保留风险提示；可取消/删除/移除 |
| 会议仅授权短信，尚未安装 | 记录首次越权与当前风险；之后安装立即 MalwareFailure |
| 会议先安装，之后允许通讯录 | 授权事务中立即 MalwareFailure，尚未判断的其他权限不阻止即时失败 |
| 会议终局后撤销权限或移除 | SessionClosed，冻结失败不可回滚 |
| 会议普通提交时仍有下载/安装残留，没有敏感授权组合 | JudgmentFailure，原因是未解除安装风险；不是提前宣称命中组合规则 |
| photo 提交时仍有任何非当前用途允许或全部相册允许 | PrivacyFailure；可靠核验/分类/处置做对的分项保留 |
| photo 按示例权重全正确后允许短信（权重4），四证据与处置全对 | P=30-4-5=21，总91，PrivacyFailure；撤销并安全结案则 P=25，总95，历史仍保留 |
| Abandon 下七项都越权允许，当前权限奖励0，历史扣35 | P下限0；明细加一条 +35 的 floor-adjustment 解释下限，最终条目合计仍为0，不删除七次错误事实 |
| 播放失败/取消，或首次扫描取消 | 不伪造完成；首次取消回 Idle，已查看/收集事实不被清空 |
| 已完成检测→重分析→取消 | 恢复 Completed，保留原完成标记与已收集证据 |
| 新任务替换旧任务，旧回调到达 | StaleRequest，不增加 revision，也不更新结果；requestId 不可历史复用 |
| 重开或切关的 sessionId 发来旧回调 | StaleSession；结束会话收到后续命令/回调则 SessionClosed |
| 少证据确认前修改任意有效状态 | revision 变化，旧确认 StaleRevision；重复无变化操作不使确认失效 |
| 连续提交、终局后重复危险动作 | 只产生一个 CaseResult，后续 SessionClosed 并返回既有结果 |
| 未结算时 Abort，再收到扫描回调 | Aborted、无结果，所有 Running 请求失效；新调查使用新 sessionId |

普通提交的未发现线索提示只含数量与来源 ID，不含未发现证据标题/结论。完整定义含正确答案，属于可信业务数据；Presenter 不得把完整 Domain 定义直接交给 View，应转换成适当显示数据。

## 定义留白、接入点与未验证事项

1. 本轮未发现与 P1 `CaseSummary` 的类型冲突。P1 目录摘要与完整 CaseDefinition 分工独立，未修改摘要或仓储接口。窗口 1 仍需提供读取完整定义、资产深度转换与资源存在性校验，接入已有案件目录；无效配置须显示不可用。
2. 三策略稳定 policyId 由窗口 1 在 Bootstrap 显式注册；Domain 已提供实现与 CreateDefault 便捷方法，没有修改 AppRoot。三案运行时内容、来源 ID、核验与分类 ID 仍需与窗口 3 的脚本映射，本轮不等待内容或 UI 也不抢写 JSON/SO。
3. 文档未指定“会议最终残留安装但未命中敏感授权组合”的枚举，本实现使用 JudgmentFailure 并保留具体原因，只有组合条件命中才 MalwareFailure。若窗口 1 需要其他产品定义，应先统一约定，不在本窗口擅改公共设计。
4. 权限题错误和当前危险分开：必要访问被拒绝但未切换放弃用途时，该项不获权限分；它不属于非必要授权，不会单独触发 PrivacyFailure。最终安全依据可靠核验、正确分类、正确处置和无当前危险，未追加“每项权限必须答对才安全”的设计外门槛。
5. 最小定义只存规则所需消息文字、媒体/来源引用与检测指标类型；角色展示、模拟指标数值/解释、媒体 Clip、授权文件等由内容与引擎适配器承载，不把实际媒体或检测引擎装入 Domain。模拟服务成功只标记教学结果可用，不主张鉴定能力。
6. 会话要求同线程串行调度；正常用户命令的当前会话校验、页面退出取消任务、返回栈、媒体生命周期、异常显示与 Application 快照均待窗口 1 接入。领域回调已有双标识过滤，仍不代替上层处理正确线程与取消。
7. CaseResult 包含冻结 sessionId/revision、两个版本、分数明细、当前隐私风险、操作记录与建议。`FinalState.Result` 故意为 null，避免结果与自身循环；会话随后 CaptureState 的 Result 持有实际冻结对象。ResolvedAtUtc 仅为显示时间，存档产生顺序应由应用级 ProgressService 单独分配。
8. 存档 DTO、Pending/Saving/Saved/Failed、结果去重保存、最高分聚合、重试与损坏恢复不在 T2 范围；不能直接把完整 Domain 定义当存档 DTO。后续保存与复盘须读取同一份冻结结果，不重新按新配置计分。
9. `.meta` 已按文本资产格式生成唯一 GUID，未让团结引擎导入验证。未启动编辑器、编译、运行测试、打开场景或验证真机；不声称 API 可编译运行、剧情可全部通关、素材已获授权或已经完成 UI 集成。
