# S6 APK 流程体验优化

日期：2026-10-30；CC。刘总要求考虑流程与用户体验，本轮基于现有代码完成首批优化。本文对交互顺序的描述取代 S5 中旧页面的展示顺序，静态检查范围、APK检查能力与Android验收边界继续保留。

## 问题与实际调整

| 原流程问题 | 本轮行为 |
| --- | --- |
| 未选文件就显示四项用途以及较长说明 | 首屏突出“选择安装包（.apk）”，说明本机读取与大小限制；选文件后再问用途 |
| 结果先展示摘要串和证书，重点事项靠后 | 先显示核实摘要、所选文件与用途，优先呈现需要核实的权限；摘要给出核实后再决定是否安装的建议 |
| 长权限列表淹没保存与下一步入口 | 保存位于详细权限前；重点项先展示5条，可展开其余；其他声明与技术信息分别展开 |
| 展开列表后用户失去阅读位置，或新结果仍停在旧文件按钮附近 | 分区展开保持内容标识；新的文件或用途报告改变标识，让结果从摘要开始 |
| 上个文件选定的用途被带入下一个文件 | 成功读取新APK时用途重置为未确定，之后由用户重新选择；取消或失败不会重置旧结果 |
| 新文件成功后静默替换未保存报告 | 更换前显示确认，说明替换条件与保存入口；取消选择或检查失败保留旧报告并明确提示 |
| 读取期间只有固定等待文字 | 原生页显示打开文件、实际已读MiB、检查清单、读取权限和清理缓存阶段；新增取消按钮 |
| 报告读取失败只能离开页面 | 添加重新读取入口，成功后清除旧错误提示 |

未确定用途时可以使用通用提示，不强制用户猜一个分类。用途选项点选后收起，仍可更改。尚未列出重点项时仍说明“不代表安全”；其他声明中保留规则未覆盖项目。

## 状态与资源边界

- 手动保存方式保持：界面明确当前报告是否保存；保存失败仍可重试。没有隐式自动保存个人文件信息。
- 更换提醒的确认回调幂等；重复点击只产生一个弹层。离页释放弹层并取消请求，迟到选择不启动新检查。
- 新文件成功后才替换当前报告；失败或取消时原结果、用途与已保存状态保留。
- 已保存报告仍显示冻结的事实和解释，详情页不能改写用途。展开技术信息只改变当前页面显示，不重写报告。
- 非重点权限默认收起，可完整展开；折叠不参与结论计算，也不表示那些权限已经安全。
- 原生读取大小来自实际复制字节数，阶段来自实际解析步骤；没有合成百分比或估计剩余时间。
- 报告中外部标签移除富文本尖括号、控制字符及Unicode格式控制，减少文字注入和方向伪装。
